# סוכן משרות Data Analytics — דוח Excel יומי במייל

הסוכן רץ **בענן, בחינם**, על GitHub Actions. בכל בוקר הוא:

1. סורק את LinkedIn, Drushim, JobMaster, AllJobs, Indeed, אתרי דרושים נוספים (GotFriends, JobKarov), עמודי קריירה של חברות (Greenhouse / Lever / Ashby / Workable / SmartRecruiters / Comeet; בנקודת ההתחלה יש כ-50 חברות), ואת הקישורים שהעלית בתיקייה `user_sources/`.
2. מאתר בעצמו מקורות חדשים: כל חברה שמופיעה בלוחות הדרושים נבדקת מול מערכות הגיוס הנפוצות, וכל לוח קריירה שנמצא עם משרות בישראל נוסף לסריקה הקבועה (`data/discovered_sources.json`).
3. פותח כל משרה פוטנציאלית וקורא את **תיאור המשרה המלא**, ואז מפעיל את 7 השלבים: כותרת, תיאור מלא, מילת מפתח חובה, מהות התפקיד והחרגות, מיקום, 20 ימים, החלטה סופית.
4. מעדכן את הרשימה המצטברת ומסיר ממנה משרות ישנות מ-20 ימים.
5. בונה קובץ `.xlsx` עם 4 לשוניות: משרות חדשות, רשימה מצטברת, מצב המקורות, מקורות ייחודיים.
6. **שולח את הקובץ במייל בשעה 10:00 בדיוק (שעון ישראל), ולעולם לא לפני כן.**

## הקמה חד-פעמית (כ-10 דקות)

### 1. יצירת App Password ב-Gmail (המייל שממנו יישלח הדוח)
1. נכנסים ל-https://myaccount.google.com/security ומוודאים שהאימות הדו-שלבי (2-Step Verification) **מופעל**.
2. נכנסים ל-https://myaccount.google.com/apppasswords
3. נותנים שם (למשל `jobs-agent`) ולוחצים Create.
4. מעתיקים את הסיסמה בת 16 התווים. היא משמשת רק את הסוכן, ואפשר לבטל אותה בכל רגע.

### 2. יצירת מאגר ב-GitHub
1. אם אין לך חשבון, פותחים חשבון חינמי ב-https://github.com/signup
2. יוצרים מאגר חדש ב-https://github.com/new, בשם למשל `data-jobs-agent`, ומגדירים אותו כ-**Public**.
   > למה Public? ב-GitHub Actions, מאגר ציבורי מקבל **דקות ריצה ללא הגבלה ובחינם**. מאגר פרטי מוגבל ל-2,000 דקות בחודש, והסוכן צורך יותר (הוא ממתין עד 10:00). במאגר נשמרות רק רשימות משרות ציבוריות. **כתובת המייל והסיסמה נשמרות כ-Secrets מוצפנים ולא נחשפות.**
3. מעלים את כל הקבצים מהתיקייה הזו: בעמוד המאגר לוחצים **uploading an existing file**, גוררים את כל התוכן כולל התיקייה `.github`, ולוחצים Commit.
   לחלופין, משורת הפקודה בתיקייה הזו (המאגר המקומי כבר מאותחל. מחליפים את USER בשם המשתמש שלך ב-GitHub):
   ```bash
   git config user.name "USER"
   git config user.email "USER@users.noreply.github.com"
   git add .
   git commit -m "Data Analytics jobs agent"
   git remote add origin https://github.com/USER/data-jobs-agent.git
   git push -u origin main
   ```
   בדחיפה הראשונה ייפתח חלון התחברות ל-GitHub בדפדפן.

### 3. הגדרת ה-Secrets
במאגר: **Settings → Secrets and variables → Actions → New repository secret**, ומוסיפים שלושה:

| Name | Value |
|---|---|
| `SMTP_USER` | כתובת ה-Gmail שממנה יישלח המייל |
| `SMTP_PASSWORD` | ה-App Password מסעיף 1 |
| `EMAIL_TO` | הכתובת שאליה יישלח הדוח (אפשר כמה כתובות, מופרדות בפסיק) |

### 4. הרשאות ו-Actions
- **Settings → Actions → General → Workflow permissions** → מסמנים **Read and write permissions** → Save.
- בלשונית **Actions** לוחצים על "I understand my workflows, go ahead and enable them" אם הכפתור מופיע.

### 5. בדיקה
**Actions → Daily Data Analytics jobs report → Run workflow** ובוחרים:
- `test-email`: סריקה קצרה ושליחת מייל בדיקה **מיד**, מסומן ‎[בדיקה]. לא משנה את הרשימה המצטברת.
- `report-only`: בונה את הדוח בלי לשלוח מייל. הקובץ זמין להורדה תחת Artifacts של הריצה.

מכאן הכול אוטומטי, ואין צורך שהמחשב שלך יהיה דלוק.

## הוספת מקורות משלך (קובץ טקסט)
מעלים קובץ `.txt` לתיקייה `user_sources/` דרך GitHub: נכנסים לתיקייה ולוחצים **Add file → Upload files**. אפשר גם לערוך את `user_sources/links.txt`.
- קישור אחד בכל שורה. שורות ריקות, רווחים ושורות שמתחילות ב-`#` לא נקראות.
- כפילויות מוסרות אוטומטית, ואין הגבלה על מספר הקישורים.
- אפשר להוסיף כל סוג קישור: עמוד קריירה של חברה, לוח Greenhouse/Lever/Comeet, אתר דרושים, או עמוד משרה בודד. הסוכן מזהה בעצמו את שיטת האיסוף המתאימה.
- אם עמוד הקריירה של החברה מבוסס על מערכת גיוס מוכרת (Comeet, Greenhouse, Lever, Ashby, Workable, SmartRecruiters, Workday, Jobvite), הסוכן מזהה אותה בקוד העמוד וקורא את המשרות ישירות ממנה, גם כשהעמוד עצמו נטען ב-JavaScript.
- קיים כבר הקובץ `user_sources/career_sites2.txt` עם 67 אתרי הקריירה שהוספת.

## איפה רואים מה קרה
- **Actions** → ריצה → **Summary**: כמה משרות נבדקו, כמה עברו, ופילוח סיבות הסינון.
- `data/state.json`: הרשימה המצטברת ותאריך השליחה האחרון.
- `reports/`: דוחות 30 הימים האחרונים.

## התאמות (`agent/config.py`)
- מילות מפתח, כותרות, תפקידי החרגה, רשימות ערים ואזורים, מקורות קבועים.
- `TREAT_HAIFA_AS_NORTH = True`: חיפה והקריות נחשבות "אזור הצפון" ומוחרגות. כדי לכלול אותן, משנים ל-`False`.
- `USE_HEBREW_KEYWORD_EQUIVALENTS = True`: התרגום העברי הישיר של מילת מפתח נחשב כמוה ("מסדי נתונים" = Databases, "פייתון" = Python, "שאילתות" = Querying, "מחסן נתונים" = Data Warehouse). כדי לדרוש את האיות האנגלי בלבד, משנים ל-`False`.

## מגבלות ידועות (בשקיפות)
- **Indeed** חוסם גישה אוטומטית (Cloudflare, ‏HTTP 403). הסוכן מנסה בכל ריצה ומתעד את הכשל בלשונית "מצב המקורות". אין דרך חינמית ואמינה לעקוף את החסימה, ומשרות Indeed ישראליות מופיעות לרוב גם ב-LinkedIn ובלוחות הישראליים.
- **חיפוש מקורות דרך מנועי חיפוש** (Bing) מבוצע כ"מאמץ מיטבי", כי מנועי חיפוש מגבילים בוטים. מנגנון הגילוי העיקרי הוא בדיקת חברות מול מערכות הגיוס, והוא אמין.
- אתרים שנטענים כולם ב-JavaScript (למשל SQLink, JobNet, Secret Tel Aviv, ועמוד הקריירה של Wix) לא מכילים משרות בקוד הדף, ולכן סורק רגיל לא יכול לקרוא אותם. אם קישור כזה מופיע בקובץ המשתמש, הוא מסומן בלשונית "מצב המקורות" כ"חלקי" עם הסבר. אם החברה משתמשת ב-Greenhouse, Lever, Comeet וכו', עדיף להוסיף את קישור הלוח שלה.
- כותרות לא סטנדרטיות (בלי המילה Analyst) נשלפות רק כשמהות התפקיד אנליטית. תפקידי ניהול (Lead, Director, Manager, ראש צוות), מחקר ואבטחה לא נשלפים בדרך הזו.
- GitHub משבית תזמונים במאגר ללא פעילות במשך 60 יום. הסוכן מבצע commit בכל יום, ולכן זה לא אמור לקרות.
